# Lesson 05-08 Concept: Build a Value With `useFactory`

## Goal

Provide a value that is computed when Angular creates the provider value, then render it in the app shell footer.

## The single new concept

`useFactory` provides a value by calling a function:

```ts
{
  provide: APP_BUILD_LABEL,
  useFactory: () => `built-at-${new Date().toISOString()}`,
}
```

Use `useValue` when the value is already known. Use `useFactory` when Angular should compute the value.

## Prior knowledge assumed

- Lesson 05-07: `InjectionToken` and `useValue`.
- Lesson 05-02: components can inject token values.
- Lesson 03-03: `App` is the shell around the routed page.

## Mental model

`useFactory` changes the provider from "here is the value" to "call this function to get the value."

```text
Token requested -> Angular runs factory -> Angular caches provider result for that injector
```

For a normal provider, Angular does not call the factory every time the template reads the injected value. The value is created for the injector and then reused.

## `useValue` versus `useFactory`

`useValue`:

```ts
{ provide: STORAGE_KEY, useValue: 'learn-angular-22-topics' }
```

The value is fixed in the provider record.

`useFactory`:

```ts
{ provide: APP_BUILD_LABEL, useFactory: () => `built-at-${new Date().toISOString()}` }
```

Angular calls the factory to obtain the value. The token consumer does not know or care how the value was made.

## This lesson's label is runtime-created

The token name is `APP_BUILD_LABEL`, but the example value is computed when the app runs in the browser:

```ts
`built-at-${new Date().toISOString()}`;
```

That is good enough for learning factory providers. It is not a production build stamp generated by the Angular build pipeline.

The useful observation is timing:

- A full browser refresh creates a new app instance and a new label.
- Navigating between routes reuses the same app shell and label.
- Reading `buildLabel` in the template does not call the factory again.

## Lazy creation

Like services, provider values are usually created when something first asks for the token. In this lesson, `App` injects `APP_BUILD_LABEL`, so the label is needed as soon as the app shell is created.

If no class injected `APP_BUILD_LABEL`, the provider could sit unused with no visible behavior.

## Factory providers can depend on other tokens

This lesson uses a simple factory with no dependencies. The broader provider shape can also list dependencies:

```ts
{
  provide: SOME_TOKEN,
  useFactory: (storageKey: string) => `using-${storageKey}`,
  deps: [STORAGE_KEY],
}
```

Angular resolves the tokens in `deps`, passes those values to the factory, and uses the factory return value as the provided value.

You do not need that dependency shape for the build label, but it is the reason factory providers matter in larger apps.

## Factory body rules

Keep factory functions small. A factory should create a value, not run an application workflow.

Good factory work:

- combine injected configuration values
- choose an implementation based on a simple flag
- create a small object from existing dependencies

Poor factory work:

- start HTTP requests
- mutate component state
- perform long-running setup that belongs in a dedicated service

## When to choose each provider shape

Use `useClass` when Angular should instantiate a class:

```ts
{ provide: Logger, useClass: ConsoleLogger }
```

Use `useValue` when the value is already known:

```ts
{ provide: STORAGE_KEY, useValue: 'learn-angular-22-topics' }
```

Use `useFactory` when the value must be computed, especially when it depends on other injected values.

## Comparison callout

Angular v15 also supported factory providers. React and Vue often compute setup values directly in app initialization. Angular lets that setup participate in DI so components can inject the result by token.

## Vocabulary checkpoint

- **Factory provider:** a provider that calls a function to create the value.
- **`deps`:** tokens Angular resolves before calling a factory.
- **Provider result:** the value Angular returns when the token is injected.
